= Transcription Core

:toc:
:toclevels: 3

*Status:* Implemented as a standalone module; not yet wired into the desktop application.

== Purpose

The transcription core turns per-track meeting audio into timestamped phrases. It is a direct
port of Sessio's local recognition engine (source: Sessio `codex/151-call-prompter` at
`8d09bba6`), so the future meeting stack can consume transcripts without depending on the
Sessio database or UI.

This is the first step of workstream W1 in xref:roadmap/Current_Roadmap.adoc[the roadmap]
(plugin platform direction, issue #242); the plugin wiring, call capture and transcript
persistence land in later tasks.

== Scope

The core provides:

* real-time transcription of several audio tracks with one shared recogniser;
* voice-activity detection and phrase segmentation per track;
* resampling from the capture rate to the recogniser's 16 kHz;
* speaker metadata (host or participant, display name) on every phrase;
* a model locator that resolves the GigaAM v3 RNN-T and Silero VAD files at runtime;
* a sherpa-onnx backend behind engine-agnostic interfaces.

It does not provide:

* audio capture or call transport;
* transcript persistence, meeting documents or history;
* summaries or the live prompter;
* speaker diarisation beyond the per-track role.

== Module layout

`src/transcription/` is split into two CMake targets:

[cols="1,3"]
|===
|Target |Contents

|`cppwiki_transcription`
|Engine-agnostic C++20 stdlib code: `TranscriptionEngine`, `PhraseSegmenter`, `Resampler`,
`ModelLocator`, tuning constants and the `ISpeechRecognizer` / `IVoiceActivityDetector` seams.
Builds and tests without any model files.

|`cppwiki_transcription_sherpa`
|`SherpaBackend` implementation of the two seams; the only target that links sherpa-onnx.
|===

The engine threads are fixed: callers of `pushAudio` only copy samples, one segmenter thread
resamples and runs each track's VAD, and one decode worker runs the recogniser, so a slow
decode never blocks capture.

Phrases are delivered through `EngineCallbacks::on_phrase` as `TranscribedPhrase`
(`track_id`, `role`, `speaker_name`, `start_ms`, `end_ms`, `text`), with times measured from
the start of the call.

== Build and models

Transcription is enabled by default and can be skipped entirely:

[source,bash]
----
# Skip the sherpa-onnx / ONNX Runtime source build and the ~160 MB model download
rtk cmake --preset debug -DCPPWIKI_ENABLE_TRANSCRIPTION=OFF
----

`cmake/Transcription.cmake` builds sherpa-onnx v1.13.8 from source (the prebuilt Linux
tarballs use the old `std::string` ABI and cannot be used with the C++ API). Model files are
downloaded into `CPPWIKI_MODELS_DIR` (default `build/<config>/transcription-models`) by
`cmake/FetchTranscriptionModels.cmake`, each verified against a pinned SHA-256:

[source,text]
----
<models>/gigaam-v3-rnnt/{encoder.int8.onnx,decoder.onnx,joiner.onnx,tokens.txt}
<models>/silero_vad.onnx
----

At runtime `locateModels` looks in `CPPWIKI_MODELS_DIR` (environment override), the installed
`share/cppwiki/models` location, and the build-tree directory, and returns a user-readable
error when nothing matches.

Tests:

[source,bash]
----
rtk ctest --test-dir build/debug -R cppwiki_transcription
----

`cppwiki_transcription_{engine,segmenter,resampler,locator}_tests` use fake VAD/recogniser
implementations and need no models. `cppwiki_transcription_model_tests` exercises the real
GigaAM and Silero files and skips gracefully when they are absent; its load tests are gated
behind `CPPWIKI_TRANSCRIPTION_LOADTEST`.

== Licensing and distribution

|===
|Component |License

|GigaAM v3 RNN-T weights (Sber, `salute-developers/GigaAM`)|MIT
|Silero VAD (`snakers4/silero-vad`)|MIT
|sherpa-onnx|Apache-2.0
|ONNX Runtime|MIT
|===

All four are permissive and compatible with the project's AGPL-3.0 license. Model weights
are *not* vendored in the repository: they are fetched at build time from the pinned
sherpa-onnx `asr-models` release asset. Any redistributable bundle that ships the model
files (installer, AppImage, DMG) must therefore include the upstream MIT notices for GigaAM
and Silero VAD alongside the application's own license. When packaging starts to include
them, add those files to the packaging step rather than to `third_party/`.
