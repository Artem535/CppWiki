= Synced Attachments v1: Implementation Plan
:toc:
:toclevels: 2

> *For agentic workers:* execute one task at a time; begin each code task with its failing test and run the stated focused verification before committing.

*Goal:* Let users attach images and arbitrary files up to 25 MiB to a wiki page, retain them offline, synchronize them through Couchbase Lite and Sync Gateway, render images inline, and save generic files through a native dialog.

*Architecture:* An attachment is a workspace-scoped record with metadata and an opaque payload. BlockNote snapshots retain only a stable cppwiki-attachment URI. The browser uploads bounded chunks through QWebChannel; the desktop bridge and repository own validation, persistence, reading, and native file access.

*Tech stack:* C++20, Qt 6 WebEngine/WebChannel/Widgets, Couchbase Lite C++, BlockNote/React/TypeScript, Vitest, CTest.

*Spec:* xref:architecture/Attachment_Storage_and_Sync_Design.adoc[Attachment Storage and Sync Design].

== Global constraints

* One file must not exceed 25 MiB; reject a too-large upload before persistence.
* Keep attachment bytes outside document snapshots; persist only stable private URIs there.
* Records in a synced workspace contain workspace_id and a Couchbase Lite Blob.
* Do not expose raw filesystem access, external application launch, or public attachment URLs to editor JavaScript.
* Images render inline through a private scheme; all other files use explicit native *Save as...*.
* A document or block deletion does not delete attachment bytes in v1.
* Archive/restore preserves IDs, metadata, and bytes.
* Do not configure or build the server. Reuse the checkout's existing desktop build and only build focused desktop/test targets.

---

== File structure

* src/storage/attachment.h and .cc define metadata, URI parsing/formatting, size validation, and repository result envelopes.
* src/storage/local_document_repository.h exposes attachment persistence/read/list operations.
* src/storage/file_document_repository.{h,cc} implements opaque local files and JSON metadata.
* src/storage/cblite_document_repository.{h,cc} implements records and CBL Blobs in the selected workspace collection.
* src/storage/workspace_archive.{h,cc} adds attachment payloads to schema version 2 archives.
* src/bridge/editor_bridge.{h,cc} owns upload sessions and native Save as...
* src/gui/attachment_scheme_handler.{h,cc} serves only authorized private attachment URIs to QWebEngine.
* src/gui/page.{h,cc} registers the scheme handler and routes generic attachment activation to the bridge.
* frontend/editor/src/blocks/AttachmentBlock.tsx implements image and generic-file blocks.
* frontend/editor/src/bridge adds the typed upload/download contract.
